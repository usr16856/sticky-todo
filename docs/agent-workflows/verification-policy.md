# 按影響範圍與風險驗證

適用於本專案的日常改動；產品特有的最低門檻繼續生效。判斷上次有效驗證以來的累積變更，不按本次修改行數判斷。證據不足時提高驗證強度，不自行將不明範圍視為小改。

| 影響範圍 | 最低必要驗證 |
|---|---|
| 純文件、註解 | 確認不影響程式、建置或產碼，檢查差異與必要引用；不跑完整 App 測試。 |
| 文案、圖片、局部 UI | 檢查資源引用、字串格式與相關建置；有畫面影響時驗證該畫面及相關狀態。無關登入、串流、回放不因局部文案修改自動重測。 |
| 功能邏輯、API、狀態處理 | 相關單元／整合測試，加上受影響流程的正常、邊界及失敗情境；編譯成功不足以替代功能驗證。 |
| 共用元件、P2P／影音 SDK、登入安全、建置設定、大範圍重構 | 擴大到受影響模組、變體與核心流程；必要時完整回歸。範圍不明時先釐清或提高驗證強度。 |

同一程式、設定、環境及適用範圍已有有效驗證時，引用實際命令、結果、快照與產物 hash，避免因換 AI 重跑。內容、相依、環境變更或證據失效時補跑受影響部分。AI 可以提高驗證強度；低於已約定的最低要求須先取得 Ben 同意。

每次改動後簡短回報：選擇此驗證範圍的理由、實際執行項目及結果、證據、未測項目與剩餘風險。未執行不能寫成通過。

發布前驗證另有獨立門檻：每週內測與正式對外發布分開定義；正式發布採較完整回歸。產出 APK 不代表所有功能通過。尚未定義的專案命令、回歸集合及發布最低門檻標為待定，不猜測命令或驗收成功。

主題與產品範圍沿用本專案規則。SpotCam Android 的 UI 修改驗證 Light／Dark；不將此產品要求自動套用到其他專案。

## Debug log 顯示與外部輸出

- Debug 版本在本機開發／測試時，保留完整 log 顯示；不得只因 AI 自行套用的一般資安原則，擅自遮蔽、刪減、停印 log，或自行調低可見的 log level。處理 log 的實作仍以使用者指定範圍為準。
- 依 build type 判斷，不依 staging／prod 環境名稱判斷；`normalStagingDebug` 與 `normalProdDebug` 的本機顯示都適用。連到 prod 服務不會讓 Debug 變成 Release，也不授權修改遠端服務的記錄或存取規則。
- 這項要求是本機 Debug 顯示政策，不代表本輪已修改 App 程式、log 開關或實際輸出，也不授權為了印 log 額外讀取憑證、變更帳號／裝置／檔案權限或繞過既有存取限制。
- Release build 與遠端服務的記錄政策維持原要求；不得把 Debug 的完整顯示要求同步套用到 Release，或移除僅供 Debug 使用的條件。
- 本機完整 log 不等於可原樣外傳。交接、Git、聊天、雲端、附件或外部上傳仍依已授權目的地及最小必要範圍處理，不對外傳送帳密、token、cookie、私鑰、授權標頭或其他可重用憑證；需要外部分享時另備適當去識別／遮蔽的副本，不因此改掉本機 Debug 顯示。
- 若既有專案的「log 不印／遮蔽」文字與本條衝突，先辨別它約束的是本機 Debug 顯示、Release、憑證讀取操作，還是外部輸出；本機 Debug 顯示依本條與使用者指示，其他界線照原規則。不以模糊的「資安要求」悄悄停印，也不藉此擴大權限或對外揭露。
