# StickyTodo 產物保留與分類

本次接入為保留規則及本機分類總覽，維持原有 .NET／WPF 建置、測試、交付與驗證要求。沒有移植 Android Gradle 控制器或啟用新的自動刪除。`bin`、`obj`、publish 或其他輸出位置只提供分類線索，不表示整個資料夾可刪。

`TODO.md`、裝置協調狀態、使用者筆記、設定、備份與鎖定資料均不是測試暫存。不得因任務結案、檔案日期、程式關閉或 Git clean 而清除；既有唯讀路線圖與裝置保留契約繼續生效。

已結案的一般驗證輸出可在來源 commit／必要差異、工具與依賴、實際結果、檔案身分／雜湊、結論及例外均完整後，另行形成精確預覽候選。交付、回退、待安裝／驗收、未結案重現、失敗／中斷及活動程序的原件保留。exe、套件、dump 或錄影不因副檔名或可重新建置就自動合格。

結案由任務 owner 確認並記錄可靠 closedAt；不由 PASS、merge 或 mtime 推定。小型原始測試證據保留三十個完整日，缺少舊時間時從首次確認結案起算，有效保留用途優先。精簡來源、結果、雜湊、必要結論及操作帳本持續留存；大型診斷須先確認必要摘錄與索引。這些是後續清理資格，不是時間到就刪除。

共用工具由全域指令定位的私人來源 `procedures/artifact-management.md` 提供。依本機 profile 與登錄位置產生歷史／新產物索引及檔案總管捷徑；不搬移或複製原件，不把機器路徑、完整清單或原始證據納入 Git。新檔與同名重建不繼承歷史用途。未知、占用、換檔、hard link、reparse、來源／工具漂移及未解除的活動狀態保留。

後續若新增受控刪除器或接入排程，仍需產品專屬驗證、固定計畫與身分／來源／占用核對、耐久帳本及唯讀中斷調和。不能只依總覽 CSV 或分類資料夾刪除；工作樹另需 owner／管理器釋放及 ignored 內容處理，不掛在測試完成事件上。
