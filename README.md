# StickyTodo

繁體中文 Windows 桌面待辦便條紙。單機離線使用，以 Markdown 作為唯一待辦資料來源；沒有 Codex skill 或全域指令整合。

## 使用

- 桌面或開始功能表的 StickyTodo 捷徑開啟便條紙。
- 「新增待辦」可勾選一個或多個專案；儲存後每個專案各建立一筆可獨立管理的待辦。
- 「編輯」會以原始完整內容比對其他專案的同文待辦，包含已完成項目。有符合項目時預設勾選同步，並列出各專案筆數與已完成數量；儲存後一起更新文字，各筆完成狀態、優先等級及位置保持獨立。比對只統一換行，不忽略空白或大小寫；不建立永久連動。取消同步即可只改目前這筆，或將它移動至另一個專案。同一專案內其他同文項目不連動。
- 待辦清單上方的「測試機使用狀態」會在啟動及每五秒背景讀取 ADB 真機，也可按「重新整理測試機」。同一台經 USB／Wi-Fi 連線時以穩定序號合併，排除模擬器。新裝置自動登記為「未標記」；點「編輯」可選未標記／閒置／使用中，使用中必填使用者與用途，改為其他狀態時清空這兩欄。更新時間自動保存，區域的收合選擇會記住。
- 測試機斷線後仍保留紀錄與原使用狀態，連線狀態不代表是否正在使用。ADB 不可用、逾時、未授權或無法取得穩定序號時顯示提示並自動重試；無法確認連線的裝置顯示「連線未知」。裝置紀錄不計入待辦數量，也不參與同文同步。
- 新增與編輯可選「高／一般／低」優先等級，新增預設一般；多專案新增採用同一選定等級，編輯時等級只套用目前這筆。未完成待辦以紅色表示高、主題文字色表示一般、藍色表示低，色彩會隨底色調整；設定的「優先等級說明」提供實際顏色範例。滑鼠提示亦可查看等級。完成項目使用淡色刪除線，取消完成後恢復等級顏色；項目不會依等級自動排序。
- 完成項目保持原位與編號，可取消完成或隱藏。
- 關閉視窗會縮到系統匣；設定或系統匣的「結束 StickyTodo」才會結束程式。
- 置頂與登入 Windows 時啟動預設關閉。重複啟動會顯示既有視窗。
- 底部右側滑桿即時調整主視窗不透明度（10～100%），並記住設定。Tab 可聚焦，方向鍵每次調整 1%，Home／End 切換最低／最高值；新增／編輯表單與快顯選單保持完全不透明，方便閱讀與輸入。
- 設定選單的「主題色」可選擇預設配色（便條黃、櫻花粉、天空藍、薄荷綠、薰衣草、雲朵灰、夜間），或以「自訂顏色…」開啟自訂主題色視窗：可拖曳選色方塊與色相滑桿、輸入色碼（`#RRGGBB`、`RRGGBB` 或 `#RGB`），或點選建議色與最近使用的 8 個自訂色。選色時便條即時預覽，按「套用」才保存；取消、Esc 或關閉視窗會還原原本顏色。選色方塊聚焦後可用方向鍵調整（Shift 加大步距）。文字、強調、懸停等顏色依底色自動推算，深色底自動改用淺色文字；切換後所有已開啟的視窗立即套用並記住設定。
- 設定選單的「開啟待辦資料檔」使用 Windows 預設 App；「選擇 App 開啟…」可針對當次操作挑選其他編輯器，不在 StickyTodo 保存程式路徑。
- 編輯表單的「刪除待辦」須再次確認；刪除後重新編號，資料檔旁保留上一版備份。外部資料變更時停用刪除，避免刪錯項目。

## 位置

- 原始碼：`.`（目前儲存庫）
- 資料：`.\TODO.md`
- 上一版資料：`.\TODO.md.bak`
- 專案選單來源：`..`
- 程式：`%LOCALAPPDATA%\Programs\StickyTodo\StickyTodo.exe`
- 設定：`%LOCALAPPDATA%\StickyTodo\settings.json`

正式執行時，專案選單來源預設為 `%USERPROFILE%\git`，資料預設為其下的 `StickyTodo\TODO.md`；上述相對路徑則以目前儲存庫為基準。專案清單讀取來源目錄的第一層非隱藏、非系統資料夾，排除以點開頭的資料夾及 `docs`、`artifacts`、`node_modules`、`bin`、`obj`。不要求 `.git`，包含 iOS 與工具資料夾，`其他` 固定放最後。

啟動時與執行中每秒掃描專案，主畫面及已開啟的新增／編輯視窗會自動反映資料夾新增、刪除及重新命名；清單沒有變化時不重建畫面。主畫面依名稱合併資料夾與有待辦的歷史分組，保留捲動及收合狀態。空專案顯示「尚無待辦」，可點「新增待辦」預選該專案；加入第一筆待辦後才寫入 Markdown，單純掃描不改寫資料或備份。資料夾消失時移除空專案，有待辦的歷史分組仍保留；資料夾重新命名不會自動搬移舊待辦。

清單刷新保留編輯草稿、優先等級、同步設定與目前選取，不自動勾選新專案，也不改變零選取狀態；選取中的專案即使資料夾消失，也保留至該次編輯結束。掃描失敗會保留上次成功的清單、顯示提示並自動重試；首次失敗仍提供歷史分組及「其他」，待辦讀寫不受影響。主畫面的「重新載入資料」與編輯器的「重新整理」也會更新專案清單。新增視窗會記住上次勾選的專案組合；舊版設定的單一專案會自動沿用。

## 資料格式與保護

測試機紀錄同樣保存在 `TODO.md`，位於文件標題後、待辦專案之前。首次發現新真機才建立區塊；定期掃描與連線狀態變化不會反覆寫檔。裝置專用寫入只替換標記內的區塊，保留待辦原文、BOM 及換行格式：

```markdown
<!-- stickytodo:devices:v1:start -->
## 測試機使用狀態

| 裝置序號 | 裝置名稱 | 狀態 | 使用者 | 用途 | 更新時間 |
| --- | --- | --- | --- | --- | --- |
| example-serial | Android Phone | 未標記 |  |  | 2026-11-05T10:30:00+08:00 |
<!-- stickytodo:devices:v1:end -->
```

序號不可重複，狀態只接受「未標記／閒置／使用中」。使用中必填使用者與用途，其餘狀態兩欄留空。各欄位為單行文字，文字中的 `|` 寫為 `\|`，反斜線寫為 `\\`；時間使用含時區的 ISO 8601 格式。可依此格式直接修改 Markdown，App 每秒重新讀取外部變更。AI 指令與操作規範尚未制定，本版未新增命令介面。

裝置編輯會合併最新待辦及其他裝置資料，同一台紀錄被外部修改時會保留草稿並要求重新載入。待辦編輯期間若僅裝置紀錄改變，草稿仍可正常儲存且保留最新裝置資料；待辦本身被修改仍走原有衝突恢復流程。裝置表格格式錯誤時保護原檔、停用修改並提示原因。含測試機區塊的資料檔須使用新版 App；舊版不支援此格式。

ADB 依序從 `ANDROID_SDK_ROOT`、`ANDROID_HOME`、`%LOCALAPPDATA%\Android\Sdk` 的 `platform-tools\adb.exe` 尋找，最後使用 PATH。偵測只查詢現有 ADB 裝置與屬性，程序有逾時限制；不代為配對或授權裝置。

```markdown
# 我的待辦

## SpotCam
<!-- stickytodo:priority=high -->
1. [ ] 首行內容
    第二行內容
2. [x] 已完成內容

## 其他
<!-- stickytodo:priority=low -->
1. [ ] 其他事情
```

使用 UTF-8；CRLF、LF 及 UTF-8 BOM 均可讀取。每個專案編號從 1 連續排列。項目內換行使用四個空白縮排，空白延續行也需縮排。App 保留文字內容，不將 Markdown 符號渲染成富文字。

優先等級也保存在同一份 Markdown，不另建資料檔：高、低使用上例的獨立 HTML 註解，必須緊接下一行的待辦項目，中間不可空行；一般省略註解。註解不屬於待辦內容，也不參與同文比對。舊資料未標示等級時視為一般，開啟時不會自動改寫資料。未知等級、重複或孤立的註解視為格式錯誤。若待辦文字本身包含相同註解字串，第一行照常放在核取方塊後，其餘行使用四格縮排，即可原樣保留。舊版 App 不支援此等級註解，請使用新版開啟含等級的資料檔。

每次存檔使用排他鎖、版本雜湊、同目錄暫存檔及原子替換，保留上一版備份；跨專案同步也只進行一次存檔。App 每秒檢查外部變更。編輯中發現外部修改時保留文字、優先等級與所選專案草稿，可選擇重新載入並將草稿另存新待辦；轉為新增後清除原同步範圍，不會以舊的項目位置覆蓋新資料。一般文字編輯器不遵守 App 鎖定協定，因此仍應避免在按儲存的同時於另一個程式儲存同一檔案。

格式錯誤時停用修改並顯示原因；原檔不會被重建或清空。修正後按重新載入。復原備份時先結束 App，再自行保留目前檔案並將 `.bak` 複製回 `TODO.md`。

## 建置與部署

需求：Windows、.NET 10 SDK。已安裝的個人 SDK 位於 `%LOCALAPPDATA%\Microsoft\dotnet`，腳本優先使用該位置，否則使用 PATH 的 dotnet。

```powershell
.\scripts\Build.ps1
.\scripts\Deploy.ps1 -SkipBuild
```

Build 先執行資料層與 WPF 表單測試，再產生符合本機架構的 self-contained Windows 發佈目錄。Deploy 複製發佈檔案並建立桌面與開始功能表捷徑，不修改資料、設定或開機啟動。更新前需結束已安裝 App。沒有自動 Git commit 或 push。

## 隔離桌面測試

主視窗保留 WindowChrome，使用 WPF `AllowsTransparency` 與 `Opacity`。WPF 會移除直接加入的 `WS_EX_LAYERED`，因此不直接呼叫 `SetLayeredWindowAttributes`，由 WPF 管理透明視窗。

App 接受 `--data-dir`、`--settings-dir`、`--project-root` 指定測試目錄。使用 `--data-dir` 時標題顯示「測試便條紙」並停用開機啟動操作。請同時指定獨立的設定目錄，避免影響正式設定。每個資料目錄只允許一個 App 執行個體。
